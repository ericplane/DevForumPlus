DataStore :GetAsync() throttling on high player counts

Bluff_006 Developer Relations
ArawDev
Jan 14

Request budgets are per-server, not per-key. If you are seeing DataStoreService throttling at high player counts, the usual cause is one call per player per heartbeat rather than a batched write through GlobalDataStore:UpdateAsync().

The pattern we recommend:

local function safeGetAsync(store, key)
	local attempts = 0
	while attempts < 3 do
		local ok, result = pcall(store.GetAsync, store, key)
		if ok then
			return result
		end
		attempts += 1
		task.wait(2 ^ attempts)  -- exponential backoff
	end
	error("GetAsync failed after 3 attempts")
end
Note that UpdateAsync counts against both the read and write budget.

local budget = DataStoreService:GetRequestBudgetForRequestType(Enum.DataStoreRequestType.GetAsync)
if budget < 5 then
	task.wait(1)
end
Why the budget is per-server

Each server gets its own request budget that refills over time. A single GetAsync per player per heartbeat drains it in seconds at 40+ players.

Ours resolves the store through game:GetService("ReplicatedStorage"):WaitForChild("Modules"):WaitForChild("DataStoreConfig") before the first save, which is where the budget goes first.
